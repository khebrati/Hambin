# Bug-report action concepts

Three interactive proposals are available at `/?preview=bug-reports` in the browser design gallery. These use Roomio's existing Material 3 semantic tokens and avatars, with light/dark, large-text, RTL, and responsive layouts. They model shared product intent for browser and native clients; no native screens or production entry points change.

1. **Quiet & familiar — Settings row.** A tonal “Report a bug / Tell us what went wrong” row below profile preferences opens a simple description form. Recommended permanent entry point: predictable and unobtrusive.
2. **Right in the moment — Party menu.** The party's overflow action opens a quick report with Video, Voice, Joining, or Other selection and a description. Mobile uses a bottom sheet; larger windows use a dialog. The party remains behind the form. Recommended supplementary entry point for issues during watching.
3. **Easy to find — Home shortcut.** A small “Something not working? Report a bug” action below Create/Join opens a form with what happened and optional expected behavior. More discoverable for an early release, with extra Home density.

These are alternatives for review, not accepted product decisions. Existing Settings is titled “Your profile” in both clients; the first concept proposes adding a separate Help & feedback section there. No feedback destination or delivery contract is approved. Sending is explicitly simulated; no API, microphone, screenshot capture, diagnostics collection, or report storage is added. No email reply or resolution promise is made. Static surrounding app content provides placement context.

Initial/empty: description starts blank and Send is disabled. Populated: a non-whitespace description enables sending; party reports also require category selection. Loading: sending feedback and disabled fields prevent repeat submission. Success: simulated acknowledgement clears the draft. Error: retained draft and Try again. Offline: retained draft and disabled Send. Selected: category and preview toggles. Pressed/focus: existing Material buttons and row interaction. Close/Escape retains the shared in-memory draft across entry points for the current gallery visit; refresh discards it. Cancel during simulated sending cancels the timer. An empty report-history screen is not applicable because no inbox/history is proposed.

Preview controls provide success, send-failure, and offline outcomes. Category and optional expected behavior are illustrative form variants; their final schema, destination, data handling, and cross-client implementation remain unresolved in `open-questions.md`. No baseline requirement or accepted decision has been changed.

Validation: production TypeScript/Vite build passed (existing large-chunk advisory remains). Chrome checks passed for all three submissions at desktop light/dark, 390px mobile, and 360px dark/large-text/RTL. No page overflow or runtime errors. Failure/retry, offline disabled submission, retained draft on Close/Escape, and success clearing passed. Desktop gallery and mobile dark/large-text/RTL sheet screenshots were visually reviewed.
