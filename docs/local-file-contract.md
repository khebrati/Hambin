# Local media contract (2026-11-13)

Production implementation authorized after DD-073 preview selection. Shared stream metadata adds `sourceKind: URL | LOCAL_FILE` (default URL for older records/clients) and `fileName` (empty for URL). POST stream/start accepts either the existing HTTPS `url`, or `{sourceKind: LOCAL_FILE, fileName}`. Only the file basename is transmitted; no file bytes, paths, size, duration, hashes or identity comparison. UTF-8 names are limited to 512 bytes and reject separators/control characters. A nonempty local source has an empty shared URL.

An explicit source replacement sends `replace: true` and the current `revision`; both are required to replace an active source atomically under its room lock. Authorization, idempotency and stream-session fencing remain unchanged. Aborting removes local playback and current device selections. Reload/restart requires selecting the local file again; room reconnect preserves an existing device selection for the same stream session.

When other viewers are connected, URL starts retain DD-074 automatic PREPARING/countdown. Local starts create a source-scoped INVITING attempt at zero, with the owner accepted and other members pending. An owner alone creates no source attempt for either kind: no readiness dialog for local files and no group preparation/countdown for URLs (DD-076). Normal player controls remain available. The same participant/consent/commit protocol is reused for group attempts. Viewers respond ACCEPTED only after their selected media opens; DECLINED/WITHDRAWN viewers have no video but retain room voice/chat. Start counts accepted non-owners and permits a subset, matching the reviewed preview. Late members may select a copy and privately catch up when no active invitation exists or after commitment; selecting during invitation participates in the pending request. Lost server invitation state after a service restart is recoverable through owner Sync, without uploading/replacing media.

Local-file attempts add `localFile: true` to group state. Any committed local-file seek/player/disconnect/timeout failure ends that attempt for everyone with FAILED. Every member receives one brief snackbar; participants restore their pre-attempt playback position/play-pause state and retain their selected file. There is no persistent sync error card. Successful seeks into different media are allowed. File mismatch is never inferred. URL attempt failure/exclusion rules retain DD-059/DD-074 behavior.

Local selection errors remain local and recover through choosing again. Player readiness/finite deadlines detect unsupported formats and unreachable timestamps. Clients must never report a device path or object URL through shared stream or diagnostics/analytics. Object URLs/security-scoped access are retained only while needed and released when replaced/leaving. Source filenames are excluded from analytics.
